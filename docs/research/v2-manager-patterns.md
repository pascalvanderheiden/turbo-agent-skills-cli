# AgentSkills.in and ASM interaction and lifecycle patterns

- **Issue:** [#40](https://github.com/pascalvanderheiden/turbo-agent-skills-cli/issues/40)
- **Researched:** 2026-10-18
- **Method:** primary sources only: the two requested sites, their authoritative linked repositories, and TASC's `CONTEXT.md`, README, and roadmap issues [#1](https://github.com/pascalvanderheiden/turbo-agent-skills-cli/issues/1) and [#39](https://github.com/pascalvanderheiden/turbo-agent-skills-cli/issues/39). Repository citations are pinned to commits where possible.

## Source identity

**AgentSkills.in** presents itself as “The Package Manager for AI Agent Skills”; its docs direct users to `npx agent-skills-cli` ([site](https://www.agentskills.in/), [docs](https://www.agentskills.in/docs)). The corresponding first-party CLI repository is `Karanjot786/agent-skills-cli`: its README identifies `agentskills.in` as the marketplace used by the `skills` CLI ([README lines 1–20](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L1-L20)).

The requested `https://yuxiaoli.github.io/asm/` page is a mirror/deployment of **Agent Skill Manager (`asm`)**, not a distinct manager. Its own HTML sets the canonical URL to `https://luongnv.com/asm/` and `sameAs` to `luongnv89/agent-skill-manager`; that repository redirects to `luongnv89/asm` ([requested page](https://yuxiaoli.github.io/asm/), [source](https://github.com/luongnv89/asm)).

## Comparison

| Area | AgentSkills.in / `agent-skills-cli` | ASM |
|---|---|---|
| **Interaction** | Scriptable CLI with an optional interactive search picker. Core verbs cover search, install, list, update, remove, doctor, audit, score, budget, and repository submission ([commands](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L63-L90)). | Agent-oriented CLI with JSON/non-interactive modes plus an optional local TUI ([overview](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L20-L44), [TUI](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L63-L68)). Bundle installation uses staged pickers in a TTY and deterministic flags otherwise ([lines 793–816](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L793-L816)). |
| **Installation** | Installs from marketplace names, GitHub/Git URLs, private Git, npm packages, or local folders ([lines 93–129](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L93-L129)). Every installing command scans before copying; critical findings block unless `--skip-audit` is explicit ([lines 81–90](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L81-L90), [151–160](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L151-L160)). | Installs from GitHub, registry, or local sources and validates/scans before install ([lines 24–44](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L24-L44)). Registry installs resolve a manifest to an exact commit ([lines 522–550](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L522-L550)). |
| **Lifecycle** | Primarily installed/not-installed, with source checks, updates, pruning, and lockfile-style `frozen` installs ([lines 65–77](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L65-L77)). | Explicit residency ladder: installed → saved/library → disabled → reference. `asm audit residency` recommends, but does not execute, demotion ([lines 190–226](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L190-L226)). `asm get` can read or temporarily borrow a skill without installation, reports resolution provenance, and applies the same pre-install scan ([lines 228–304](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L228-L304)). |
| **Creation** | A skill is a folder containing `SKILL.md`; the documented authoring checks are `validate`, `score`, then `export` ([lines 278–298](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L278-L298)). No guided scaffold is documented. | Full authoring loop: `init` scaffold, `link` for live development, security audit/inspect, `eval`, GitHub push/install, then registry publish ([lines 385–475](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L385-L475)). |
| **Organization** | `.skillsrc` or `.skillsrc.json` supplies private sources and defaults; project config wins over home config ([lines 235–262](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L235-L262)). It exposes per-skill context estimates and budget-based selection ([lines 164–172](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L164-L172)). | Cross-provider inventory, local library/activation, disable/enable, token statistics, local tags, and reference borrowing are separate mechanisms ([command table](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L630-L705)). Optional dependencies use caller-owned acquire/release leases rather than implicit permanent installation ([lines 306–349](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L306-L349)). |
| **Dedicated repository** | No dedicated manifest registry or PR-publish repository is documented. `skills submit-repo owner/repo` instead asks the hosted marketplace to index every `SKILL.md` in an existing repository ([lines 131–135](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L131-L135)). | `luongnv89/asm-registry` is a dedicated, curated manifest repository. Each manifest points to a source repository and pinned commit ([registry README lines 1–18](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/README.md#L1-L18)); its schema constrains repository, commit, tags, and security verdict ([schema lines 38–83](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/schema/manifest.v1.json#L38-L83)). |
| **Sharing** | Share an ordinary repository and submit it for marketplace indexing; installs can also consume Git/npm/local sources directly. | `asm publish` previews or opens a registry PR ([ASM lines 452–475](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L452-L475)). Manual publication is also PR-based ([registry contributing lines 6–45](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/CONTRIBUTING.md#L6-L45)). CI validates schema and author identity, detects duplicates/typosquats, and independently scans the pinned source ([workflow lines 35–88](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/.github/workflows/validate-pr.yml#L35-L88), [88–154](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/.github/workflows/validate-pr.yml#L88-L154), [154–220](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/.github/workflows/validate-pr.yml#L154-L220)). |
| **Categorization** | No CLI category/tag model is documented. The site has a `/categories` route, but its directly fetched primary response exposes no taxonomy ([categories](https://www.agentskills.in/categories)). | Registry manifests carry category tags, while users can add local tags without modifying `SKILL.md`; filters use AND semantics ([schema lines 64–73](https://github.com/luongnv89/asm-registry/blob/23a2e9e5cbae376adae960ec5091934b5a52d5dc/schema/manifest.v1.json#L64-L73), [ASM lines 727–734](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L727-L734)). |
| **Bundles** | No named bundle/collection object is documented. `skills budget` chooses relevant skills under a token ceiling; it is selection, not a versioned or shareable set ([lines 164–172](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L164-L172)). | First-class bundle lifecycle: list, install, create, show, modify, export, remove; JSON files are installable and eight predefined bundles ship with ASM ([lines 675–681](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L675-L681), [793–825](https://github.com/luongnv89/asm/blob/0671173ba533264f8c0dee1961ee9edaeb4b9516/README.md#L793-L825)). |
| **Agent scope and telemetry** | Targets 45 assistants ([lines 174–233](https://github.com/Karanjot786/agent-skills-cli/blob/465cad3c22178f565cc067897a272b8cdfd8bece/README.md#L174-L233)). ## TASC disposition

TASC already has stronger domain separation than either manager: **Installation** versus **Skill Source**, explicit **Tracking/Adoption**, a non-installing **Watchlist**, versioned **Local State**, immutable run artifacts, **Evaluation**, **Consistency Check**, **Security Check**, and evidence-backed **Insights** and remediation. Its v1 **Adapter Target** is GitHub Copilot ([roadmap #1](https://github.com/pascalvanderheiden/turbo-agent-skills-cli/issues/1)); v2 adds TASC Profile, Skill Category, and Skill Bundle questions ([roadmap #39](https://github.com/pascalvanderheiden/turbo-agent-skills-cli/issues/39)).

| Pattern | Decision | TASC-specific treatment |
|---|---|---|
| Pre-install validation/security scan | **ADOPT** | Run a revision-pinned **Security Check** before an approved installation. Preserve TASC's evidence, severity/confidence, and policy-warning approval model; do not trust a marketplace verdict as sufficient evidence. |
| Pinned source manifests and CI supply-chain gates | **ADAPT** | Reuse the useful shape—immutable **Source Revision**, repository/path, digest, tags, declared security result—and typosquat/identity/duplicate checks. Store/verify it through TASC's local-first model and existing GitHub workflows; do not require a TASC-operated registry. |
| Central crawl-and-index marketplace | **REJECT** | TASC should not operate or depend on a hosted catalog in v2. It conflicts with the local-first trust boundary and duplicates GitHub/`gh` discovery. A **Skill Source** remains explicit and provenance-bearing. |
| Default vendor telemetry | **REJECT** | Keep command use, skill content, **Evaluation** traces, and **Local State** local unless the user explicitly chooses an external operation. |
| Scriptable CLI plus optional rich interaction | **ADOPT** | Matches TASC's existing CLI/Copilot-agent parity and issue #39's rich terminal goal. Preserve stable JSON, TTY detection, and non-interactive flags; a TUI must not become the only interface. |
| Guided authoring scaffold/live workspace loop | **ADAPT** | `asm init`/`link` is a useful interaction precedent, but TASC must retain **Skill Authoring → Skill Draft → deterministic validation → optional installation/sharing**, and only edit an explicit **Skill Workspace**. |
| Four-tier residency ladder and zero-install `get` | **ADAPT** | Add preview/borrow behavior without creating an **Installation** or silently writing **Local State**. Convert residency/context-cost observations into **Insights** with bounded **Remediation Proposals**; do not import ASM's installed/library/disabled terminology or confuse reference use with a **Watchlist**. |
| Token/attention-cost accounting | **ADOPT** | Treat resident metadata/body cost as deterministic local metrics feeding `tasc stats` and context-cost **Insights**. Do not let budget ranking replace Evaluation quality or Security evidence. |
| Local tags separate from upstream tags | **ADOPT** | Model **Skill Category** as user-owned Local State while retaining upstream tags as source metadata. Keep provenance clear and allow deterministic multi-tag filtering. |
| Named, exportable bundle lifecycle | **ADOPT** | Use create/show/modify/install/export/remove as a behavioral baseline for **Skill Bundle** and **Portable Skill Bundle**. TASC installation must add revision pinning, transaction/rollback, explicit approval, Tracking, and preflight Security/Consistency checks. |
| Budget-filtered results as “bundle” | **REJECT** | A transient ranked subset is not a named, versioned, shareable deployment manifest. Keep budget selection separate from Skill Bundle identity. |
| Project/home config precedence | **ADAPT** | Useful input for unresolved **TASC Profile** inheritance. Specify precedence, migration, and user/project overrides explicitly rather than copying `.skillsrc` semantics. |
| Optional skill dependency leases | **ADAPT LATER** | Record as a bundle/dependency design input. Before adoption, define identity, revision pinning, cycle/conflict handling, approval, cleanup ownership, and how dependencies participate in **Consistency Checks**, Security Checks, Tracking, and portable export. |
| Multi-assistant fan-out | **REJECT FOR V1/V2 CORE** | Keep the assistant-neutral domain and adapter seam, but avoid copying 45/21-provider breadth while GitHub Copilot is the declared v1 target. Add adapters only through a later scoped decision. |
| Manager “eval/score” as TASC Evaluation | **REJECT** | Quality scores may be inputs, never substitutes for TASC's versioned **Evaluation Suite**, Tasks, Trials, evidence, baselines, and immutable Run Artifacts. |
| Manager duplicate/overlap audit as TASC Consistency | **ADAPT** | Duplicate/semantic-overlap detection can contribute evidence, but TASC must preserve Ownership Claims, Precedence Rules, terminology drift, conflict/coverage findings, confidence, suppressions, and traceable remediation. |

## Conclusions

1. **Best AgentSkills.in precedents:** broad source syntax, team config precedence, pre-install scanning, and token-budget visibility. Its hosted indexing and default telemetry do not fit TASC's trust boundary.
2. **Best ASM precedents:** CLI/TUI duality, non-destructive residency advice, zero-install reference access, local/upstream tag separation, pinned registry manifests, PR/CI publication, and first-class portable bundles.
3. **TASC should remain distinct:** neither product provides TASC's complete Evaluation, Consistency, Security-evidence, Insight lifecycle, Tracking/Adoption, or Watchlist contracts. Borrow interactions and manifest mechanics, not their domain model wholesale.
4. **Recommended v2 priority:** define Skill Bundle/Portable Skill Bundle and Skill Category using ASM's interaction patterns, then add context-cost Insights and preview/borrow semantics. Defer dependency leases and any hosted catalog until their effects on Local State, Tracking, Watchlists, Security, and Consistency are specified.

## Verification limits

- AgentSkills.in is client-rendered. Direct primary-source retrieval confirmed the landing/docs text and the categories-route footer, but not an enumerable site taxonomy; the report therefore says categorization is **not documented/verified**, not that it cannot exist.
- Product behavior was compared from first-party documentation and repository configuration, not by executing either third-party CLI. Security claims are documented capabilities, not an independent security audit.
