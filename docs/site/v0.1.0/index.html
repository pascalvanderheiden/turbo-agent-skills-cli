Install and verify

Use the release-pinned installer for TASC 0.1.0. Each installer detects a supported platform, downloads the matching release archive, verifies its SHA-256 against SHA256SUMS.txt, and installs to a user-writable directory. Inspect the shell installer or PowerShell installer before running it.

curl -fsSL https://raw.githubusercontent.com/pascalvanderheiden/turbo-agent-skills-cli/v0.1.0/install.sh | bash
iex (irm https://raw.githubusercontent.com/pascalvanderheiden/turbo-agent-skills-cli/v0.1.0/install.ps1)

The Bash installer supports Linux x64/ARM64, macOS Intel/Apple Silicon, and Windows x64 under Bash. The native PowerShell installer supports Windows x64. Unix-like systems install to ~/.local/bin; Windows installs to %LOCALAPPDATA%\Programs\TASC. Set TASC_INSTALL_DIR to choose another writable directory.

After installation, initialize TASC and inspect your local inventory:

tasc setup
tasc skill list
tasc state status

tasc setup offers the optional first-party TASC Command Skill; it never installs the Skill automatically.

The corresponding v0.1.0 release publishes five verified targets:

  • Linux x64: x86_64-unknown-linux-gnu
  • Linux ARM64: aarch64-unknown-linux-gnu
  • macOS Intel: x86_64-apple-darwin
  • macOS Apple Silicon: aarch64-apple-darwin
  • Windows x64: x86_64-pc-windows-msvc

The installers verify the selected archive against the published checksum before extraction. You can also download the archive and manifest directly and verify the matching filename using sha256sum, shasum -a 256, or PowerShell Get-FileHash -Algorithm SHA256.

Use GitHub CLI (gh) for GitHub discovery and skill lifecycle operations. A working GitHub CLI authentication is required for remote operations; local state and analysis commands work without network access. Waza is optional; the deterministic package smoke Evaluation does not execute skill instructions or require a model.

Manage skills safely

Inventory local Copilot skills and see which ones are tracked in TASC Local State:

tasc skill list --json

Install, update, and remove delegate to supported gh skill commands. Start with a dry run; an interactive mutation shows a plan and asks for approval. Non-interactive mutations require --yes. Updating or removing locally modified content additionally requires --force and approval.

tasc skill install review --source owner/repo --dry-run
tasc skill install review --source owner/repo --yes

Adopting a discovered but untracked Installation records it without reinstalling or changing skill files. Removal only deletes the selected recorded skill directory. TASC never silently updates skills from a Watchlist or Insight.

Local State is stored at $XDG_STATE_HOME/tasc/state.json or ~/.local/state/tasc/state.json; set TASC_STATE_PATH to select a different file. Evaluation, Consistency, Watch, and Insight evidence is kept in separate immutable artifact directories beside the state file. Credentials are not copied into Local State.

Discover and watch sources

Search and preview delegate to GitHub CLI's supported skill capabilities and are explicitly bound to github.com, regardless of an inherited GH_HOST setting. Search does not install files or write Local State. Name-based preview must resolve to one exact match; use a returned Skill Identity or exact skill path when results are ambiguous.

tasc search review --format json

Watchlists

Watchlists record GitHub sources or selected skill paths. A Watch Check compares revisions and writes immutable evidence; it does not install or update a skill.

tasc watch add owner/repo --dry-run
tasc watch list --json
tasc watch check

Adding or removing a Watchlist entry requires explicit approval. A changed upstream revision is a report for you to review, not authorization to modify an Installation.

Run an Evaluation

Version 0.1.0 supports deterministic package-only smoke validation of a local SKILL.md. It checks package metadata such as frontmatter name and description; it does not run scenarios, invoke a model, or execute skill instructions.

tasc eval run skill:file:///path/to/.github/skills/example --json

Each run records the package digest, identity, known source revision and target, analyzer configuration, outcomes, and diagnostics in an immutable sibling <state-stem>.evaluations directory separate from Local State. A changed or removed package does not rewrite old evidence.

tasc eval list --json

Scenario execution is reported as not_run. The optional --waza check reports the external capability status; a Waza installation alone does not enable model-backed execution in this release.

Check Consistency

Select at least two Skill Identities explicitly, or opt into all discovered skills. The deterministic local check compares declared dependencies, ownership, precedence, assumptions, trigger phrases, the current directory glossary, non-goals, and prior artifacts.

tasc consistency check <skill-id-1> <skill-id-2> --json
tasc consistency check --all-installed

Findings include evidence, confidence, severity, and revision status. Lexical trigger overlap is a warning, not proof of runtime collision; missing declarations are not treated as conflicts. Inferred analysis is explicitly marked not_run; no model or live composition probe is invoked. Each check is an immutable artifact in a sibling <state-stem>.consistency-checks directory.

Review Insights and proposals

Generate a ranked snapshot from observed Installation lifecycle states, the latest Evaluation per Skill Identity, and the latest Consistency findings:

tasc insight generate

Priority is a deterministic ordering of impact, confidence, urgency, affected Installations, freshness, and stable Insight ID—not a universal quality score. Snapshots retain their contributing evidence. Changed evidence creates a new snapshot and marks the previous one stale.

Insight status and scoped, reasoned, expiring suppressions are append-only lifecycle records; they do not rewrite evidence. Suppressed Insights are omitted from the default actionable list but remain inspectable with --all.

tasc insight list --all
tasc insight status example-insight acknowledged
tasc insight suppress --reason "reviewed" --expires-in-days 30 example-insight

Users can record new, acknowledged, snoozed, and resolved. stale and inconclusive describe evidence or snapshot state; suppressed is driven by an active suppression record.

tasc insight propose <insight-id>

A Remediation Proposal explains scope, risk, prerequisites, reversibility, affected evidence, and expected verification. Proposals are informational only. This release has no command that applies a proposal or edits an Installation or Skill Workspace.

Author a skill

tasc skill create guides authoring in an explicitly selected Skill Workspace. It previews the proposed skill and requires approval before writing; --dry-run never writes. Draft records are kept in the Workspace and incomplete drafts are excluded from ready-skill discovery.

tasc skill create --workspace ./skill-workspace --name review-helper --dry-run

Resume a draft with tasc skill resume, inspect drafts with tasc skill drafts, and use tasc skill validate before treating a draft as ready. A ready draft is not installed or published by authoring.

Evaluation checks local package metadata but does not prove instructions are correct, safe, or effective. Do not treat a passing smoke Evaluation as approval to install or share a Skill Draft.

Security and trust boundaries

tasc security check performs bounded static analysis of selected local skills or an explicitly selected Workspace. It checks for exposed secrets, unsafe permissions and instructions, injection or exfiltration patterns, risky executable content, supply-chain indicators, and suspicious references. It does not execute skills or fetch external references.

tasc security check --help

Security findings are evidence, not a guarantee that content is safe. Review the source and skill instructions before installing or enabling them. Use exact-fingerprint suppressions with reasons and expiration; Evaluation and Consistency results are not security verdicts.

Release archives have SHA-256 checksums, a CycloneDX SBOM, GitHub build-provenance attestations, and a separate SBOM attestation. Verify checksums and GitHub attestations before use. Platform-native code signing is not provided in this release.

Understand the architecture

  • tasc-core contains canonical domain types and state models.
  • tasc-agent contains shared application services, adapters, and immutable artifact storage.
  • tasc-cli provides the tasc command-line interface.

The CLI delegates GitHub skill lifecycle operations to GitHub CLI and keeps Local State, Evaluations, Consistency Checks, and Insights local by default. See the domain glossary, CLI overview, and the project repository for contributor context.

Troubleshoot

  • Remote command says gh is missing: install GitHub CLI. Authenticate with gh auth login before search, preview, install, or update.
  • Unsupported GitHub skill operation: check the installed gh capability; TASC reports unsupported operations rather than substituting a different API.
  • Local changes block update or removal: inspect and preserve the modifications, then explicitly use --force only if you approve replacing them.
  • Evaluation is inconclusive or not run: this release performs package smoke checks only; model-backed scenario execution is not available.
  • An Insight is stale or suppressed: generate fresh evidence; use insight list --all or insight show to inspect retained evidence and history.
  • State appears missing: check TASC_STATE_PATH and the XDG/default state path. Run artifacts are stored separately and are not a backup of Local State.

Local inventory, state, and analysis do not require a network connection. Use --offline to reject remote discovery before invoking GitHub CLI.

Upgrade and recover releases

Stable releases use protected SemVer tags. Each version is immutable after publication; assets are never replaced in place. Download and verify the new archive, stop using the old executable, and manually replace it. TASC has no self-update command.

The five supported archives target Linux x64/ARM64, macOS Intel/Apple Silicon, and Windows x64. No Rust toolchain is needed to run a downloaded binary. GitHub CLI is required for remote discovery and lifecycle operations; the tested gh skill discovery contract is GitHub CLI 2.101.0. Waza is optional and model-backed Evaluation execution is not available. Version 0.1.0 reads existing version-1 Local State; review release notes for any later schema migration.

To verify an archive's GitHub build provenance, install a current GitHub CLI and run gh attestation verify <archive> --repo pascalvanderheiden/turbo-agent-skills-cli. To verify the separate CycloneDX attestation, add --predicate-type https://cyclonedx.org/bom. Inspect the published BOM as JSON with python3 -m json.tool tasc.cdx.json; the output lists the binary's components and dependency relationships.

Check the release history for supported operating systems, compatibility notes, dependency ranges, schema migrations, known limitations, and release-specific instructions. The initial release may not be available until its release is published.

If a release is defective, maintainers mark the affected release as non-latest/prerelease and warn users in its notes. The correction is a new higher SemVer release; the defective tag and its published assets remain unchanged. Follow the warning and upgrade instructions rather than attempting to reuse or modify the old version.

Manual archive replacement is the supported recovery path. There is no automatic downgrade or self-update. Current-stable and a short previous-release window are intended for security and critical fixes; older versions are upgrade-only.

Repository maintainers can find protected-tag and release approval setup in the release runbook.
